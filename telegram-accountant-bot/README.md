حسابیار — بات حسابدارِ کسب‌وکارهای کوچک
========================================

یک بات تلگرام سبک و فارسی که مثل یک حسابدار جیبی برای کسب‌وکارهای خرد کار می‌کند.
صاحب کسب‌وکار خرج‌ها و فروش‌هایش را با زبان طبیعی برای بات می‌فرستد و بات:

- 🏷 **متناسب با صنفِ شما**: در شروع با یک لمس می‌پرسد چه کاری می‌کنید (آنلاین‌شاپ، نمایشگاه خودرو، مغازه، کافه، خدمات) و مثال‌ها و دسته‌بندی‌ها را با همان کار جور می‌کند
- 🟢🔴 هزینه/درآمد را می‌فهمد و **دسته‌بندی** می‌کند (کلیدواژه‌ای، یا هوشمند با LLM)
- 📊 **گزارش** روزانه/هفتگی/ماهانه و 📈 **داشبورد تصویری** (نمودار) می‌دهد
- 📒 **دفتر طلب و بدهی + چک** با **یادآوری خودکار سررسید** (چند روز قبل، روزِ سررسید، معوق‌ها) و دکمه‌ی **«✅ تسویه» زیرِ خودِ یادآوری** — وصول شد، همان‌جا ببند
- 🧾 **تاریخچه‌ی فاکتور** (`/invoices`): هر فاکتور قبلی را با یک لمس دوباره برای مشتری بفرست
- 🔗 **لینک فاکتور برای مشتری**: زیر هر فاکتور یک لینک می‌آید؛ مشتری بازش می‌کند، فاکتورش را می‌گیرد و ⭐ امتیاز می‌دهد
- ⏰ **یادآوری بدهی به خودِ مشتری** (`/remind`): با تأیید شما، پیام مؤدبانه مستقیم برای بدهکار می‌رود
- 🏬 **شعبه‌ها** (`/branches`): به هر شعبه یک کد بدهید؛ ثبت‌های کارمند در دفترِ شما با برچسبِ همان شعبه می‌نشیند
- 👤 **دفترچه‌ی مشتریان**: هر طرف‌حساب یک‌بار ذخیره می‌شود؛ «رضا» در همه‌ی فاکتورها و دفتر، **یک نفر** است
- 📄 **صورتحساب طرف‌حساب**: کارتِ تمیزِ «مانده حساب شما…» با فاکتورها و مانده‌ی دفتر، آماده‌ی فوروارد به بدهکار
- 🌙 **خلاصه‌ی خودکار شب**: هر شب یک جمع‌بندیِ کوتاه از فروش/خرجِ امروز (فقط اگر فعال بوده‌ای)
- 💵 **نمای دلاری** (`/dollar`): هر تراکنش با **نرخ دلارِ همان روز** حساب می‌شود تا بفهمی رشدت واقعی است یا فقط تورمی — «تومانی ↑۲۱٪ ولی دلاری ↓۱۶٪»
- 🧾 **فاکتور فروش** با کالاهای ذخیره‌شده (لمسی)، تخفیف/ارسال، و خروجی **عکس + PDF**
- 🎙 **ثبت با صدا**: پیام صوتی (ویس) را به متنِ فارسی تبدیل و مثل متن ثبت می‌کند (اختیاری)
- 📸 **فاکتور از هر جا**: عکس، فایل/PDF، یا لینک را با OCR می‌خواند (اختیاری)
- 👥 **حالت گروه**: بات را در گروهِ مالیِ شرکت اضافه کنید تا درخواست‌ها/پرداخت‌های بین اعضا را (با تأیید) ثبت کند و «وضعیت گروه» بدهد
- ⭐ **اشتراک درون‌بات**: دوره‌ی آزمایشی رایگان + پرداخت **کارت‌به‌کارت** یا **درگاه زرین‌پال**
- 📥 **خروجی اکسل**، 📦 **پشتیبان کامل**، 🔎 **جست‌وجو** و ↩️ **لغو** تراکنش
- 🧾 **ارسال فاکتور به سامانه‌ی مودیان** (فعلاً اسکلت/حالت آزمایشی)

همه‌چیز داخل تلگرام؛ بدون نصب اپ، بدون یادگیری نرم‌افزار سنگین.

> فاز ۱ (دفترداری) و فاز ۲ (اشتراک/پرداخت) کامل‌اند. درگاه زرین‌پال و اسکلت
> مودیان اضافه شده‌اند؛ یکپارچگی گواهی‌شده‌ی مودیان در نقشه‌ی راه است.

## 🚀 راه‌اندازی

### ۱) پیش‌نیاز
- پایتون ۳.۱۱ به بالا
- یک توکن بات از [@BotFather](https://t.me/BotFather)
- یک اسپردشیت Google Sheets + کلید Service Account (پایین را ببینید)

### ۲) نصب
```bash
cd telegram-accountant-bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### ۳) تنظیمات
```bash
cp .env.example .env
```

سه مقدار در `.env` الزامی‌اند:

- `BOT_TOKEN` — از [@BotFather](https://t.me/BotFather)
- `GOOGLE_SERVICE_ACCOUNT_JSON_B64` — کلید JSON سرویس‌اکانت گوگل به‌صورت base64
  (`base64 -w0 service-account.json`)
- `GOOGLE_SHEET_ID` — شناسه‌ی اسپردشیت (از URL آن)

> **آماده‌سازی Google Sheets (یک‌بار):** در [Google Cloud](https://console.cloud.google.com)
> یک پروژه بسازید، **Google Sheets API** و **Google Drive API** را فعال کنید،
> یک **Service Account** با کلید JSON بسازید، یک اسپردشیت خالی درست کنید و آن را
> با ایمیل سرویس‌اکانت به‌عنوان **Editor** به اشتراک بگذارید.
> **فایل JSON را هیچ‌وقت داخل مخزن commit نکنید؛** فقط از متغیر محیطی خوانده می‌شود.

> 🗂 **معماری داده — یک اسپردشیت برای هر کسب‌وکار:**
> اسپردشیتِ بالا **مرکزی** است و فقط رجیستری را نگه می‌دارد: `users`،
> `subscriptions`، `payments`، `rates`، `branches`، `branch_members`، `sequences`.
> هنگام اولین `/start`، برای هر کاربر یک **اسپردشیت اختصاصی** ساخته می‌شود که
> دفترِ خودش است: `transactions`، `ledger_entries`، `invoices`، `invoice_items`،
> `products`، `group_events`، `customers`. شناسه‌اش در ستون `sheet_id` رجیستری
> ذخیره می‌شود.
>
> برای این کار `DRIVE_PARENT_FOLDER_ID` را تنظیم کنید: یک پوشه در Drive خودتان
> بسازید و آن را با ایمیل سرویس‌اکانت **Editor** کنید. (سرویس‌اکانت به‌تنهایی
> کوتای Drive ندارد و بدون پوشه‌ی والد، ساختِ فایل شکست می‌خورد.)

داده در حافظه نگه داشته می‌شود و هر ۵ ثانیه دسته‌ای روی شیت نوشته می‌شود، پس
خواندن‌ها سریع‌اند و به Rate Limit گوگل نمی‌خورند.

### ۴) اجرا
```bash
python -m hesabyar
```

## 📸 خواندن فاکتور از هر جا (اختیاری)

کسب‌وکارهای کوچک فاکتورها را به شکل‌های مختلف می‌فرستند؛ بات همه را می‌خواند:

- 📸 **عکس** (دوربین یا گالری)
- 📄 **فایل** تصویری یا **PDF** (اولین صفحه‌ی PDF خودکار به تصویر تبدیل می‌شود)
- 🔗 **لینک** مستقیم به عکس/PDF فاکتور (با محافظت در برابر SSRF و سقف اندازه)

وقتی **استخراج هوشمند** روشن باشد (`USE_LLM_PARSER`)، علاوه بر مبلغ و دسته،
**نام فروشنده، تاریخ فاکتور و شماره فاکتور** هم از متن درمی‌آید؛ در غیر این
صورت با heuristicهای قاعده‌محور (regex) به‌صورت best-effort.

خواندن با یک سرویس تصویری سازگار با API نوع OpenAI انجام می‌شود. چون دسترسی
به این سرویس‌ها از داخل ایران محدود است، پیشنهاد می‌شود آن را روی یک **سرور خارج
از ایران** میزبانی کنید و آدرسش را در `.env` بگذارید:

```
OCR_BASE_URL=https://your-proxy.example.com/v1
OCR_API_KEY=...
OCR_MODEL=gpt-4o-mini
```

اگر خالی بماند، بقیه‌ی امکانات کار می‌کنند و فقط خواندن خودکار عکس غیرفعال است.

## 🎙 ثبت با صدا (اختیاری)

صاحبان کسب‌وکار معمولاً به‌جای تایپ، **ویس** می‌فرستند. اگر یک سرویس تبدیل
گفتار به متن تنظیم شود، بات ویس را می‌شنود، به متن تبدیل می‌کند، «شنیدم: …» را
نشان می‌دهد و بعد دقیقاً مثل یک پیام متنی ثبت/مسیریابی می‌کند (چه ثبت تراکنش،
چه داخل یک فلو مثل صدور فاکتور).

سرویس باید یک درگاهِ **سازگار با API نوع OpenAI** (`audio/transcriptions`، مثل
Whisper) باشد که برای فارسی خوب کار می‌کند:

```
STT_BASE_URL=https://your-proxy.example.com/v1
STT_API_KEY=...
STT_MODEL=whisper-1
STT_LANGUAGE=fa
```

> نکته: ربات‌های مصرفیِ «ویس‌به‌متن» تلگرام (مثل @VoiceToTextRobot) برای این
> کار مناسب نیستند، چون تلگرام ارتباط **بات‌به‌بات** را نمی‌دهد؛ به یک **API**
> نیاز است. اگر `STT_*` را خالی بگذارید ولی `OCR_*` تنظیم باشد، از همان
> اعتبارنامه استفاده می‌شود.

## 👥 حالت گروه (دفتر مالی تیمی)

بات را می‌توانید به گروهِ مالیِ یک شرکت اضافه کنید تا رویدادهای مالیِ بین اعضا
را یادداشت کند — دقیقاً مثل «کارمند الف از کارمند ب درخواست پرداخت داد» و بعد
«ب پرداخت کرد».

- بات پیام‌ها را می‌بیند و وقتی یک **درخواست پرداخت**، **پرداخت**، یا **فروش/هزینه‌ی
  خودِ کسب‌وکار** («۵ میلیون فروختم») تشخیص دهد، پیش از ثبت یک دکمه‌ی
  «✅ ثبت کن / ❌ نه» می‌گذارد تا چیزی اشتباه ثبت نشود.
- فروش/هزینه‌ها در **دفترِ خودِ گروه** ثبت می‌شوند (جدا از دفترِ شخصیِ اعضا)، پس برای
  مغازه‌ی دونفره یا کسب‌وکار خانوادگی مناسب است.
- برای کم‌کردنِ نویز، در گروه فقط جملاتی ثبت می‌شوند که **فعلِ مالیِ صریح** (فروختم،
  دادم، پرداختم…) و **مبلغِ معنادار** داشته باشند؛ «جلسه ساعت ۳» چیزی ثبت نمی‌کند.
- طرفِ پرداخت با **@منشن یا ریپلای** مشخص می‌شود؛ خودِ شخص از روی فرستنده‌ی
  پیام. اگر پرداختی به یک درخواستِ بازِ همان فرد بخورد، آن درخواست خودکار
  **تسویه** می‌شود.
- `/balance` وضعیت گروه را می‌دهد: درخواست‌های باز + پرداخت‌های اخیر.

> ⚠️ **لازم:** برای اینکه بات همه‌ی پیام‌های گروه را ببیند، در BotFather حالتِ
> حریمِ گروه را خاموش کنید: `/setprivacy` → انتخاب بات → **Disable**. سپس بات را
> از گروه حذف و دوباره اضافه کنید.
>
> 🔍 **نشانه‌ی اینکه یادتان رفته:** در گروه، **دستورها کار می‌کنند** (مثل `/balance`)
> ولی پیامِ معمولی («۵ میلیون فروختم») **هیچ جوابی نمی‌گیرد** — چون تلگرام آن پیام
> را اصلاً به بات نمی‌دهد.

## 💵 نمای دلاری — رشدِ واقعی یا اسمی؟

در ایران رشدِ تومانیِ درآمد لزوماً یعنی رشدِ واقعی نیست. `/dollar` هر تراکنش را با
**نرخ دلارِ روزِ خودش** حساب می‌کند (نه نرخ امروز)، پس خرید در دلارِ ارزان و فروش در
دلارِ گران خودش را نشان می‌دهد:

```
💵 نمای دلاری — این ماه
🟢 درآمد: ۱۵۰٬۰۰۰٬۰۰۰ تومان ≈ $۱٬۶۸۵
💰 مانده: ۱۰۵٬۵۰۰٬۰۰۰ تومان ≈ $۱٬۱۸۵

مقایسه‌ی درآمد با ماه قبل
به تومان: ↑ ۲۱٪
به دلار:  ↓ ۱۶٪
⚠️ درآمدت تومانی بالا رفته ولی دلاری کم شده — رشدِ اسمی است، نه واقعی.
```

**ثبت نرخ، دو راه دارد:**

- **خودکار از کانال:** اگر کانالی دارید که هر روز قیمت دلار را می‌گذارد، شناسه‌اش را
  در `RATE_CHANNEL_ID` بگذارید و بات را **ادمینِ آن کانال** کنید. پست‌ها خودکار
  خوانده می‌شوند (فقط عددی که واقعاً نرخ دلار باشد؛ «سال ۱۴۰۵» یا قیمت طلا ثبت نمی‌شود).
- **دستی:** مدیر با `/rate ۸۹۰۰۰` نرخ امروز را ثبت می‌کند. `/rate` بدون عدد، نرخ فعلی
  را نشان می‌دهد.

روزهایی که نرخ ثبت نشده، آخرین نرخِ **پیش از** آن روز استفاده می‌شود (نرخِ آینده هرگز).

## ⭐ اشتراک و درآمدزایی

مدل درآمد همان مدل اثبات‌شده در بازار ایران است: **اشتراک ماهانه با پرداخت
کارت‌به‌کارت**.

- **دوره‌ی آزمایشی رایگان**: هر کاربر جدید به‌طور خودکار `TRIAL_DAYS` روز
  (پیش‌فرض ۱۴) اعتبار می‌گیرد.
- **سه سطح**: 🥉 برنزی (دفترداری روزمره، با امضای بات پای فاکتور) — 🥈 نقره‌ای
  (بدون امضا + ویس + عکس فاکتور + صورتحساب) — 🥇 طلایی (+ گروه/شعبه + نمای دلاری).
  هر سطح ماهانه و سالانه دارد؛ `hesabyar/plans.py` قابل‌تنظیم است.
- **خرید**: کاربر دکمه‌ی «⭐ اشتراک» → انتخاب پلن → بات شماره‌کارت و مبلغ را
  نشان می‌دهد → کاربر «کد پیگیری» یا «عکس رسید» می‌فرستد.
- **تأیید مدیر**: درخواست برای مدیران (`ADMIN_IDS`) با دکمه‌های «✅ تأیید /
  ❌ رد» ارسال می‌شود؛ با تأیید، اشتراک به‌صورت خودکار تمدید و به کاربر
  اطلاع داده می‌شود.
- **محدودسازی**: با پایان اشتراک، ثبت هزینه/درآمد و صدور فاکتور نیاز به
  تمدید دارد؛ گزارش‌ها، دفتر و خروجی اکسل همچنان در دسترس‌اند (داده‌ی کاربر
  هرگز گروگان گرفته نمی‌شود — این را صریح به کاربر می‌گوییم).
- **هشدار پایان اشتراک**: ۳ روز و ۱ روز مانده به انقضا (و روزِ انقضا) پیام
  خودکار با خلاصه‌ی ارزشِ ثبت‌شده‌ی خودِ کاربر + دکمه‌های تمدیدِ یک‌لمسی.

**دو روش پرداخت** (با `PAYMENT_METHOD`):
- `card` — کارت‌به‌کارت با تأیید دستی مدیر.
- `zarinpal` — درگاه آنلاین؛ کاربر لینک پرداخت می‌گیرد، «بررسی پرداخت» را
  می‌زند و اشتراکش **خودکار** فعال می‌شود (نیاز به `ZARINPAL_MERCHANT_ID`).

## 🛠 ابزارهای روزمره

- 📈 `/dashboard` (یا دکمه‌ی «داشبورد تصویری») — نمودار درآمد/هزینه‌ی چند ماه
  اخیر، سهم دسته‌های هزینه، و شاخص‌های کلیدی به‌صورت یک تصویر.
- 📥 `/export` — خروجی اکسل تراکنش‌های ماه جاری.
- 📦 `/backup` — پشتیبان کامل داده‌ها (اکسل چندشیتی: تراکنش‌ها، طلب/بدهی، فاکتورها).
- 🔎 `/search کلمه` — جست‌وجو در شرح و دسته‌ی تراکنش‌ها.
- ↩️ `/undo` یا دکمه‌ی «لغو این ثبت» زیر هر تراکنش.

پشتیبان‌گیری **هفتگی خودکار** هم فعال است (با `BACKUP_WEEKLY`): کل اسپردشیت
به‌صورت اکسل برای مدیران ارسال می‌شود. خودِ Google Sheets هم History نسخه دارد.

## 🧾 سامانه‌ی مودیان (اسکلت)

پس از صدور هر فاکتور، دکمه‌ی «ارسال به مودیان» ظاهر می‌شود. ماژول
`services/moadian.py` نگاشت داده به ساختار صورتحساب و یک کلاینت را آماده
می‌کند و در نبود گواهی، **حالت آزمایشی (dry-run)** اجرا می‌شود.

> ⚠️ این نسخه **گواهی‌شده نیست**. ارسال واقعی به سازمان امور مالیاتی به
> کلید/گواهی اختصاصی، امضای دیجیتال و دست‌دادن رمزنگاری نیاز دارد که باید
> جداگانه پیاده و اعتبارسنجی شود.

## 🌐 استقرار (Deployment)

معماری این پروژه دقیقاً برای شرایط ایران چیده شده — همان مدلی که برای بات‌های
مشابه در عمل جواب داده است:

- **بات** را می‌توان روی یک سرور کوچک (داخل یا خارج) با `python -m hesabyar` اجرا کرد.
- **پرداخت اشتراک** در فاز اول به‌صورت **کارت‌به‌کارت** انجام می‌شود (مدل اثبات‌شده)؛
  در فاز بعد درگاه پرداخت ایرانی (زرین‌پال/بله) و اشتراک خودکار اضافه می‌شود.
- **سرویس OCR/هوش مصنوعی** روی سرور خارجی تا محدودیت دسترسی حل شود.

نمونه‌ی سرویس systemd:
```ini
[Unit]
Description=Hesabyar Telegram Bot
After=network.target

[Service]
WorkingDirectory=/opt/hesabyar/telegram-accountant-bot
ExecStart=/opt/hesabyar/telegram-accountant-bot/.venv/bin/python -m hesabyar
Restart=always
EnvironmentFile=/opt/hesabyar/telegram-accountant-bot/.env

[Install]
WantedBy=multi-user.target
```
